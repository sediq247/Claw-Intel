## Capability boundary

The Trading Room token lookup queries an exact token address on one selected network and displays provider source, retrieval time and limitations. A separately confirmed order writes only to a user-owned virtual USDC balance and position ledger, using fresh USD-denominated provider observations; it never writes to a blockchain. The four-chain War Room discovery set is enforced independently from the Trading Room's supported address lookups.

## Production blockers

The app does not enable on-chain order execution. Provider credentials, contractual use rights, live rate behavior, freshness, failover, and deployment health need verification in the target environment. During the 2026-11-20 audit, Docker could not connect to its engine and local PostgreSQL/API ports were unreachable; migrations were not applied.

## NEAR wallet support decision

The official [NEP-413 specification](https://github.com/near/NEPs/blob/master/neps/nep-0413.md) defines domain-bound off-chain message signing with a 32-byte nonce, recipient and a Borsh/SHA-256 Ed25519 payload. The official Wallet Selector API documents `signMessage` and notes current support is wallet/network specific; the HOT SDK documents its NEAR sign-message adapter. These paths were researched but are not included in the app yet. A dependency installation experiment with the current Meteor/HOT packages caused `npm audit` to report 24 vulnerable findings (including high severity); those added dependencies were removed, and the original frontend dependency set was reinstalled with zero advisories reported by `npm ci`. A reviewed adapter plan and dependency remediation are required before integrating Meteor/HOT. The backend does not claim NEAR signature support.
